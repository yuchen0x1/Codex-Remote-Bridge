# v4.2.0 发布前暴露面审计

## 1. 总览

目标：本项目 Web、WPF/.NET、Android APK、SwiftUI 安装包。项目已开源，公开 JS/可反编译二进制是预期行为，重点是阻止私钥/运行状态误打包、正确授权与发行真实性。

静态扫描 `public/`：8 个文件，未命中扫描器规则；原始启发式分数 100/A，仅表示此规则集未发现问题，不是安全证明。安装资产会在草稿发布后另行核验。发行身份验证目前为中风险：Android 可本地签名，Windows/macOS 发行签名与清单认证尚缺。

## 2. 发现清单

| 编号 | 严重度 | 问题 | 分析途径 |
|---|---|---|---|
| PACKAGE-SCOPE | 中 | macOS 原脚本复制整个仓库，排除项未覆盖 Android 签名目录 | 展开安装包读取文件 |
| WINDOWS-SYMBOLS | 低 | 默认 dotnet publish 可能携带调试符号 | .NET/PDB 元数据检查 |
| RELEASE-IDENTITY | 中 | Windows/macOS 缺发行者签名，更新清单无独立签名 | 替换资产/清单后重新计算哈希无法靠 SHA-256 阻止 |
| LEGACY-READONLY | 高（代码已修复，部署需轮换） | 旧 `master:ro` 格式直接包含主凭据 | 读取共享连接字符串 |

## 3. 逐项证据与修复

- `scripts/build-codex-mini-app.sh` 原 `rsync` 复制仓库并排除少数目录。改为只包含 server.js、package.json、LICENSE、src、public 和 bin；签名、构建缓存、测试和私有状态不会进入允许列表。
- `scripts/build-codex-max-windows.ps1` 发布显式使用 `DebugType=None`、`DebugSymbols=false`；调试构建保持可调试。
- `.github/workflows/release.yml` 改为草稿发布。实际 Android CI 没有 signing Secrets，需要本地签名与资产校验后公开。没有把 debug keystore 当作 Release 密钥。
- `src/security/index.js` 只读 token 使用独立 HMAC；服务端决定 scope，客户端不能通过声明读写权限提权。会话/实时连接撤销有 HTTP/TCP 行为测试。
- 未发现 public/ 包含私钥；静态扫描不涵盖全部运行时安全问题。扫描日志只保存在忽略目录 `output/evolution/`。

## 4. 客户端无法解决的问题

开源桌面客户端无法保密其 JS 或本地算法，不应为防阅读添加混淆/反调试。长期访问令牌只在运行时生成并保存在用户数据目录，签名私钥只在本地忽略目录保管，不写进产品包、清单或仓库。

鉴权在桥接服务端执行；如果电脑本身已被控制，不能靠修改客户端加固恢复信任。发行签名、清单认证和已泄露主令牌的轮换不能用字符串混淆替代。

## 5. 修复顺序

1. P0：拒绝泄漏的旧只读格式；已分享者需轮换真实部署主令牌。
2. P1：使用允许列表打包，在草稿内核对资产与 APK 签名，再公开。
3. P1 后续：配置 Windows/macOS 发行证书及清单签名。当前发布说明明确限制。
4. P2：控制符号与体积，不改变开源项目的可审查性，不引入影响正常排错的反调试。
