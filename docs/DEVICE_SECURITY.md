# 设备会话与只读配对

## 使用方法

1. 在已连接的 Web 页面打开「配对二维码」。新设备默认只读；需要发送消息、审批或操作电脑时，明确选择读写。
2. 使用实际可达的局域网地址打开页面再分享二维码；`localhost`/`127.0.0.1` 地址仅指向扫码设备自身。
3. 配对码有效期为 90 秒，只能兑换一次。生成失败会显示错误，不再降级分享长期主令牌。
4. 「设置 → 配置 → 已连接设备」显示有效会话、权限、最近访问时间和到期时间。刷新读取当前服务状态；撤销立即使该会话及关联实时连接失效。

设备名称来自浏览器 User-Agent，不是经过身份认证的人名。列表只包含会话，不包含每个持有长期 token 的客户端。会话默认绝对有效期为 24 小时，刷新页面不会延长服务端到期时间；服务重启清空全部会话。当前会话按钮禁用，避免误断开管理页面。

## 权限与轮换

- 只读凭据以 HMAC-SHA256 从主令牌派生，使用独立上下文，不包含主令牌。旧的 `主令牌:ro` 不再被接受。
- **旧格式已经泄露主令牌本身**。仅升级代码不能收回别人拿到的主令牌。曾分享旧格式链接的用户必须在电脑端轮换主令牌，随后重新配对。
- 只读设备可以签发只读配对码，但不能升级为读写；不能查看设备列表或撤销其他设备。
- 主令牌轮换同时清空所有内存会话、未兑换配对码，并断开已失效的 WebSocket。调用方收到新令牌后需用新链接重新连接。
- 单设备撤销只撤销该会话。持有主令牌的客户端仍可重新建立会话；撤销这类访问需要轮换主令牌。
- 会话 token 仅在内存中存储其哈希；管理列表返回独立随机 ID，不返回 token 或哈希。
- WebSocket 接受现有主/只读 token 与会话 Cookie/header；浏览器必须与服务同源。连接上限 64，单个客户端消息上限 64 KiB；该状态通道只接受非分片文本和控制帧。

## API（兼容性说明）

| 请求 | 权限 | 返回/行为 |
|---|---|---|
| `GET /codex/pairing-code?scope=read-only` | 已鉴权 | 一次性只读配对码；`scope=read-write` 对只读调用方仍降为只读 |
| `GET /codex/pairing-code` | 已鉴权 | 为兼容原有客户端，省略 scope 时继承调用方权限；Web UI 显式传只读 |
| `POST /codex/pair`，`{"code":"123456"}` | 一次性配对码 | 建立 HttpOnly 会话 Cookie |
| `GET /codex/sessions` | 读写 | `{ok,sessions:[{id,deviceName,scope,createdAt,lastSeenAt,expiresAt,current}]}` |
| `POST /codex/sessions`，`{"id":"会话 UUID"}` | 读写 | `{ok,revoked}`；重复撤销返回 `revoked:false` |
| `POST /codex/rotate-token` | 读写 | 返回新主令牌和连接地址，并撤销旧凭据 |

未登录返回 401，只读管理请求返回 403，格式错误返回 400。旧版 header/query/cookie 主令牌接入保持兼容。以上会话管理不修改 Codex 账户或聊天数据。

## 数据目录

默认仍是 `~/.codex-max`。`CODEX_MAX_STATE_DIR`（兼容 `CODEX_MINI_STATE_DIR`）下保存 `state.json`、`token`、`db/` 和 `certs/`。自定义目录此前可能遗漏队列和证书路径，本次统一到指定目录。不会自动搬移或删除旧目录数据；证书路径变化可能生成新证书，已固定旧指纹的客户端需要核对后重新配对。

JSON 队列仍不提供跨进程事务保证，不能将执行日志理解为可自动恢复的完整任务队列。HTTPS 自签名证书、首次指纹信任和发行签名仍需按各客户端文档配置。
